# 可交互流体风场实现

拉格朗日视角跟欧拉视角

![](https://picx.zhimg.com/v2-e9ccb98fa6e82787dd780c8d0554bd43_1440w.jpg)

拉格朗日视角一般将介质视为粒子（或微小网格）的集合，粒子会随着介质一起移动，通过计算每个粒子的运动状态和受力情况来表现介质的变化。
欧拉视角则通常将介质占有的空间切分为一个个小网格，对每个小格子计算格子内介质的状态、输入输出情况，以及对其他的格子的影响。

要计算某一位置点的风力，如果采用拉格朗日视角，就需要获得单位时间内经过该位置点的平均粒子速度，这样显然不太现实，因为单位时间内经过该点的粒子概率较低。如果采用欧拉视角，只需要查找该点所位于的格子位置，进而可以直接读出平均速度。

## 实现

### 基础设置

-   **Sim Target 改成 GPUCompute Sim**：  
    流体模拟的计算量极其庞大（每个网格每帧都要算扩散、对流、投影）。如果用 CPU 算，帧率会掉到个位数。改成 GPU，就是把 N-S 方程的网格计算交给显卡并行处理，这是做流体模拟的前提。
    
-   **Fixed Bounds（固定边界）**：  
    流体是不断向外扩散的。如果没有固定边界，计算范围会无限扩大，显存直接爆炸。Fixed Bounds 规定了流体只能在特定的盒子里运动，超出边界就忽略或反弹。
    

----------

### 一、User Exposed（用户参数）

**放在系统（System）级别，用来和外界（材质、蓝图、其他发射器）沟通的“窗口”。**

#### 1. `WindFieldRT` (Texture Render Target 类型的变量)

-   **是什么**：一张可以被 GPU 读写、且能被 UE 材质采样的纹理（图）。
    
-   **作用**：**作为输出调试的RT**。  
    你在 Niagara 里算完了速度场、压力场，这些东西是存在 Niagara 内部的，材质（Material）看不见。你需要把算好的数据“画”到 `WindFieldRT` 这张图上。然后你就可以在 UE 里建一个材质，把这张图贴上去，在视口里看到风是怎么吹的。
    
-   **为什么是 Texture Render Target 类型**：因为你需要把 Niagara 计算的结果输出给外部（材质或蓝图）用，这个变量就是输出管道的“接头”。
    

#### 2. `resolution` (int 类型)

-   **是什么**：一个整数（比如 128、256、512）。
    
-   **作用**：**作为到 render target 的分辨率**。  
    决定了那张 `WindFieldRT` 图片到底有多清晰。分辨率 256 表示纹理是 256x256。分辨率越高，流体细节越丰富，但显卡计算压力就越大。你可以在蓝图里把这个值传给 Niagara，方便随时调整模拟精度。
    

----------

### 二、Emitter Attribute（发射器属性）

**放在发射器（Emitter）级别，是实际进行流体计算的“工作台”。**

#### 3. `VelocityGrid` (Grid3D Collection 类型)

-   **是什么**：Niagara 专门用来做 3D 网格模拟的数据结构（相当于论文里的欧拉网格）。
    
-   **`Num Attribute = 3`**：代表这个网格里，每个格子要存 **3 个属性**。
    
-   **作用**：**用来存储整个三维空间的速度场（u, v, w）**。  
    结合你之前学的论文，三维流体速度就是一个向量 `(u, v, w)`。这里设置 3 个属性，正好对应 X、Y、Z 三个方向的速度。这个变量是**模拟的核心载体**，所有的扩散、对流、投影都会在这个 Grid 上进行。
    

#### 4. `RT_WindField` (Render Target 2D 类型)

-   **是什么**：这是一个指向 `WindFieldRT` 的“数据接口（Data Interface）”。
    
-   **`Over Render Target Format = RGBA 16f`**：  
    这是一个非常重要的格式设置。流体数据（比如速度值）是小数，而且范围可能很大。用普通的 8 位整数（0-255）会严重丢失精度，导致数值发散。`RGBA 16f` 表示用半浮点（16位浮点数）来存储，精度足够且性能好。R、G、B 通道正好用来存速度的 X、Y、Z 分量。
    
-   **`Render Target User Parameter = 刚刚创建的 WindFieldRT`**：  
    这就是**“接线”**。意思是：把我在发射器里算出来的数据，通过这个接口，输送到系统级的 `WindFieldRT` 这张图上去。
    
-   **作用**：**把 `VelocityGrid` 里的速度数据，写进 2D 纹理里，方便输出或调试**。

## Module脚本编写：从 3D Grid 到 2D RT 导出

### 一、 核心逻辑：为什么要这么折腾？

在 Niagara 流体模拟中，有两个核心的“数据容器”：

1.  **`VelocityGrid` (Grid3D Collection)**：用于在 GPU 内部进行复杂流体计算（N-S方程）的 3D 网格。
    
2.  **`RT_WindField` (Render Target 2D)**：用于输出给外部（UE材质、蓝图）进行显示或交互的 2D 纹理。
    

**痛点**：GPU 内部的 3D 网格数据，外部材质无法直接读取。必须把 3D 数据“拍扁”成一张 2D 图片。  
**解决方案（Z轴切片平铺到Y轴）**：  
想象你有一本 3D 的书：

-   **X 轴** = 书的宽度
    
-   **Y 轴** = 书的高度
    
-   **Z 轴** = 书的页数（深度）  
    我们将书一页页撕下来，从上到下拼成一张长卷轴。
    
-   **图片宽度** = `X`
    
-   **图片高度** = `Y * Z`
    
-   **最终 RT 分辨率** = `(X, Y*Z)`
    
-   _示例：128x128x128 的 3D 网格，RT 尺寸设为 (128, 16384)_
    

----------

### 二、 模块拆解（NMS Modules）

#### 1. `NMS_SetResolution` (初始化尺寸蓝图)

-   **运行时机**：只在模拟开始前运行一次（Emitter Spawn 阶段）。
    
-   **作用**：根据输入的分辨率参数（`Resolution`），同时规划好 3D 网格和 2D 纹理的尺寸。
    
-   **内部节点连线**：
    
    -   **输入**：`RT` (Render Target 2D 数据接口)、`Grid` (Grid3D 数据接口)、`Resolution` (Int)。
        
    -   **计算**：`Multiply` 节点（A = Resolution，B = Resolution）。
        
    -   **设置 3D 网格**：`Set Num Cells` 节点（NumCellsX, Y, Z 都连入 `Resolution`）。
        
    -   **设置 2D 图片**：`Set Render Target Size` 节点（Width = `Resolution`，Height = `Multiply` 的计算结果）。
        

### 2. `NMS_ExportToRT` (数据导出搬运工)

-   **作用**：将 3D 网格里的速度数据，转换成颜色，写入到 2D 图片里。
    
-   **运行时机**：在每帧计算结束后（Emitter Update 阶段）。
    
-   **核心流程（逐格子遍历）**：
    
    1.  `Execution Index to Grid Index`：通过执行索引，找到当前处理的是 3D 网格的哪个坐标（X, Y, Z）。
        
    2.  `Get Previous Vector Value`：读取当前坐标在上一帧的速度向量（Vector）。
        
    3.  `Break Vector`：把速度向量拆解为 X、Y、Z 分量。
        
    4.  `Make Color from Vector` (UE5) / `Make Linear Color` (UE4)：把 X、Y、Z 打包成 R、G、B 颜色。
        
    5.  `Set Render Target Value`：计算该格子对应的 2D 平铺坐标，将颜色写入 `RT_WindField`。
        
-   **调试方法**：在 Grid3D 里手动改一下值，看 RT 会不会跟着变。变了就是成功。
